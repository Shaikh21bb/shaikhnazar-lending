# SHAIKH Sales Agent — один рабочий сценарий

Текущий MVP: один WhatsApp Sales Agent для Shyraq.ai. Владелец заполняет проверенные сведения о продукте, выбирает модель, проверяет диалог и включает ответы. Цепочка локального режима: **WhatsApp Business → Docker-мост на Mac → Ollama → WhatsApp Business**. n8n больше не участвует в ответах. Старый workflow сохранён в `n8n/` только как архив; его контейнер и данные не нужны для нового запуска.

## Запуск на Mac

Требуются Docker Desktop, Ollama, интернет и уже настроенный `.env.worker.local` с `BRIDGE_BASE_URL`, `WHATSAPP_BRIDGE_SECRET` и `BRIDGE_AGENT_ID`. Не добавляйте этот файл, API-ключи и данные WhatsApp-сессии в Git. Для нового проекта также нужны серверные переменные и миграции, описанные ниже.

```bash
./start-whatsapp.command
```

Скрипт проверяет Docker и Ollama, запускает Ollama при необходимости и поднимает один Docker-сервис. На сайте: **Агенты → Шаихназар → Обучить агента** — внесите только подтверждённые факты о Shyraq.ai, цену (если известна), частые вопросы и желаемый следующий шаг. Затем выберите модель и проверьте несколько реплик в тестовом чате. Только после этого нажмите **Включить ответы**. Если номер ещё не связан, откройте **WhatsApp · QR** и сканируйте код через WhatsApp Business → Связанные устройства.

Команды управления:

```bash
./enable-sales-agent.command   # разрешить локальные автоответы
./disable-sales-agent.command  # пауза без потери WhatsApp-связи
./stop-whatsapp.command        # остановить мост и Ollama, запущенную этим проектом
docker compose -f compose.whatsapp.yaml ps
docker compose -f compose.whatsapp.yaml logs --tail=50 whatsapp-bridge
```

Настройка в панели имеет приоритет: AI должен быть включён **и** на сайте, **и** в локальном мосте. Кнопка сайта меняет оба состояния; скрипты позволяют отдельно поставить локальную паузу. Запуск `start-whatsapp.command` не включает ответы автоматически. Выбранная в панели модель применяется без пересоздания контейнера. Доступны `qwen3.5:9b-mlx`, `llama3.1:8b`, `qwen3:1.7b`; более маленькая модель может отвечать быстрее, но качество нужно проверить на ваших вопросах. Для Ollama API-ключ не нужен.

Если n8n остался запущенным после обновления старой установки, остановите **только** его старый контейнер. Его Docker volume сохраните: `docker compose down -v` не используйте. Старый открытый адрес `localhost:5678` больше не показывает рабочий путь ответов.

## Что сохраняется и что пока не работает

- Память каждого клиента и новые переписки находятся в приватном Docker volume `whatsapp-session` (`sales-history/` и `sales-transcripts/`). Они переживают остановку/пересоздание контейнера, но пока **не отображаются** в разделе «Диалоги» на сайте. Не удаляйте volume.
- Тестовый чат использует выбранную модель и материалы, но не отправляет сообщение в WhatsApp.
- Локальный режим не создаёт задачи календаря и не выполняет передачу менеджеру автоматически. Агенту запрещено обещать это клиенту.
- Если Mac выключен, спит, Docker/Ollama остановлены или связь с WhatsApp разорвана, ответов нет. Это **не** облачный бот 24/7.
- QR-мост работает через неофициальное связанное устройство WhatsApp Web. Это риск для номера; для коммерческого круглосуточного сервиса нужна официальная интеграция Meta и постоянно работающий сервер.
- OpenRouter можно выбрать в панели с личным ключом владельца. Бесплатные модели имеют ограничения; ключи покупателей и изоляция их аккаунтов как полноценный SaaS пока не готовы. QR-мост всё равно требует включённого Mac.
- В старых таблицах проекта ещё есть браузерный доступ. До проверки и закрытия политик доступа не вводите конфиденциальные сведения и не подключайте реальных покупателей к общему кабинету.

## Новая установка сервера

Для QR-режима используйте `supabase-migration-10-whatsapp-qr.sql`, `supabase/migrations/20260926170505_local_agent_control.sql` и, если нужен OpenRouter, `supabase/migrations/20260926181000_agent_provider_keys.sql`. В существующем Shaikh.digital эти миграции уже применялись; не запускайте повторно полные схемы без проверки состояния базы.

В серверной среде нужны `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `AUTH_SECRET`, `WHATSAPP_DELIVERY_MODE=qr`, `WHATSAPP_BRIDGE_SECRET` и `WHATSAPP_LOCAL_AGENT_ENABLED=true`. Секреты никогда не передаются в браузер и не хранятся в репозитории. `.env.worker.local` на Mac должен содержать тот же `WHATSAPP_BRIDGE_SECRET` и публичный HTTPS-адрес сайта.

Официальный WhatsApp Cloud API, Telegram, календарь и старая схема n8n остались в исходном коде для обратной совместимости, но не являются частью этого локального MVP.

