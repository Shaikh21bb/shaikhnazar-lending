# SHAIKH — портфолио и клиентский Agent Hub

Основной клиентский сценарий — приватный Agent Hub на `/hub.html`: один агент, заметки, внутренний календарь, журнал доходов и расходов, OpenRouter BYOK и личный Telegram-бот. Старый WhatsApp Sales Agent для Shyraq.ai сохранён как отдельный legacy-сценарий для владельца и менеджеров; он не используется клиентскими аккаунтами.

## Публичное портфолио

Главная страница `/` — отдельная публичная витрина проектов. Клиентская платформа и её существующие сценарии остаются на `login.html` и `dashboard.html`.

Чтобы добавить проект в портфолио:

1. Добавьте скриншот в `images/`.
2. Скопируйте один объект в `js/portfolio-data.js` и задайте уникальный `id`.
3. Заполните честные описания на русском и казахском, статус (`live`, `demo` или `private`), теги и ссылку.
4. Для демо без публичной ссылки оставьте `link: null`. Для закрытого кабинета используйте статус `private`, не публикуйте общий логин или пароль.

Если готового скриншота нет, используйте стилизованную обложку: `visual: 'cover'`, `visualTheme` и двуязычный `coverLabel`. Это лучше, чем прикреплять к проекту чужой или выдуманный макет.

Не добавляйте выдуманные результаты, клиентов, отзывы или метрики. Если на скриншоте демонстрационные данные, укажите это в описании проекта.

## Клиентский Agent Hub

Клиентские аккаунты открываются на `/hub.html`. Это не CRM: у каждого аккаунта один приватный операционный агент с общей памятью между сайтом и его Telegram-ботом.

Первая версия умеет:

- вести диалог в веб-кабинете;
- создавать и находить приватные заметки;
- добавлять события во внутренний календарь;
- записывать доходы и расходы и считать итог за период;
- безопасно импортировать до 300 операций из CSV без доступа платформы к банковскому аккаунту;
- использовать личный ключ OpenRouter клиента, чтобы расходы и лимиты AI оставались под его контролем;
- подключать отдельного Telegram-бота клиента через BotFather и одноразовую ссылку привязки;
- по желанию синхронизировать события с Google Calendar через OAuth.

Ключи OpenRouter и токены Telegram проверяются перед подключением, шифруются на сервере и никогда не возвращаются в браузер. В production обязателен отдельный `CREDENTIALS_ENCRYPTION_KEY`; fallback на `AUTH_SECRET` разрешён только при локальной разработке. Если Preview и Production используют одну базу Supabase, им нужен один и тот же `CREDENTIALS_ENCRYPTION_KEY` — иначе подключение, созданное в одной среде, нельзя расшифровать в другой. Для полностью изолированного preview используйте отдельную базу и отдельный ключ. Примените миграции из `supabase/migrations/` до публикации кода.

Без Google OAuth календарь остаётся полностью внутренним. После подключения платформа синхронизирует события с основным Google Calendar и может подтянуть его события обратно. Для финансов доступен только явный ввод и CSV-импорт: прямого доступа к банку, переводов и платежей у агента нет.

Для Google Calendar создайте OAuth Web client, добавьте точный redirect URI `https://shaikh.digital/api/hub/google-calendar/callback` и задайте серверные `GOOGLE_CALENDAR_CLIENT_ID` и `GOOGLE_CALENDAR_CLIENT_SECRET`. Коннектор запрашивает только scope событий календаря, использует Authorization Code + PKCE и хранит access/refresh token в зашифрованном виде. Пока переменные не заданы, карточка интеграции показывает, что её должен настроить владелец, и не обещает рабочее подключение.

Владелец создаёт клиентские доступы на `/admin.html`. Роль аккаунта хранится в базе: `owner` открывает старую служебную панель, `client` — Agent Hub. Старые аккаунты менеджеров сохраняются для прежнего sales-сценария.

## Запуск на Mac

Требуются Docker Desktop, Ollama, интернет и уже настроенный `.env.worker.local` с `BRIDGE_BASE_URL`, `WHATSAPP_BRIDGE_SECRET` и `BRIDGE_AGENT_ID`. Не добавляйте этот файл, API-ключи и данные WhatsApp-сессии в Git. Для нового проекта также нужны серверные переменные и миграции, описанные ниже.

```bash
./start-whatsapp.command
```

Скрипт проверяет Docker и Ollama, запускает Ollama при необходимости и поднимает один Docker-сервис. На сайте: **Агенты → Шаихназар → Обучить агента** — внесите только подтверждённые факты о Shyraq.ai, цену (если известна), частые вопросы и желаемый следующий шаг. Затем выберите модель и проверьте несколько реплик в тестовом чате. Только после этого нажмите **Включить ответы**. Если номер ещё не связан, откройте **WhatsApp · QR** и сканируйте код через WhatsApp Business → Связанные устройства.

Команды управления:

```bash
./enable-sales-agent.command   # разрешить локальные автоответы
./disable-sales-agent.command  # пауза без потери WhatsApp-связи
./stop-whatsapp.command        # остановить мост и Ollama, запущенную этим проектом
docker compose -f compose.whatsapp.yaml ps
docker compose -f compose.whatsapp.yaml logs --tail=50 whatsapp-bridge
```

Настройка в панели имеет приоритет: AI должен быть включён **и** на сайте, **и** в локальном мосте. Кнопка сайта меняет оба состояния; скрипты позволяют отдельно поставить локальную паузу. Запуск `start-whatsapp.command` не включает ответы автоматически. Выбранная в панели модель применяется без пересоздания контейнера. Доступны `qwen3.5:9b-mlx`, `llama3.1:8b`, `qwen3:1.7b`; более маленькая модель может отвечать быстрее, но качество нужно проверить на ваших вопросах. Для Ollama API-ключ не нужен.

Если n8n остался запущенным после обновления старой установки, остановите **только** его старый контейнер. Его Docker volume сохраните: `docker compose down -v` не используйте. Старый открытый адрес `localhost:5678` больше не показывает рабочий путь ответов.

## Что сохраняется и что пока не работает

- Память каждого клиента и новые переписки находятся в приватном Docker volume `whatsapp-session` (`sales-history/` и `sales-transcripts/`). Они переживают остановку/пересоздание контейнера, но пока **не отображаются** в разделе «Диалоги» на сайте. Не удаляйте volume.
- Тестовый чат использует выбранную модель и материалы, но не отправляет сообщение в WhatsApp.
- Локальный режим не создаёт задачи календаря и не выполняет передачу менеджеру автоматически. Агенту запрещено обещать это клиенту.
- Если Mac выключен, спит, Docker/Ollama остановлены или связь с WhatsApp разорвана, ответов нет. Это **не** облачный бот 24/7.
- QR-мост работает через неофициальное связанное устройство WhatsApp Web. Это риск для номера; для коммерческого круглосуточного сервиса нужна официальная интеграция Meta и постоянно работающий сервер.
- OpenRouter можно выбрать в старой панели Sales Agent с ключом владельца. Это отдельный legacy-сценарий; клиентские ключи и данные нового Agent Hub находятся в других server-only таблицах. QR-мост всё равно требует включённого Mac.
- Старая sales-панель тоже должна работать только через аутентифицированный серверный маршрут. После публикации серверного шлюза обязательно примените migration с блокировкой legacy RLS; до этого не считайте старые таблицы закрытыми. Новые заметки, сообщения, подключения и финансы уже находятся в отдельных server-only таблицах.

## Новая установка сервера

Для QR-режима используйте `supabase-migration-10-whatsapp-qr.sql`, `supabase/migrations/20260926170505_local_agent_control.sql` и, если нужен OpenRouter, `supabase/migrations/20260926181000_agent_provider_keys.sql`. В существующем Shaikh.digital эти миграции уже применялись; не запускайте повторно полные схемы без проверки состояния базы.

В серверной среде нужны `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `AUTH_SECRET`, `CREDENTIALS_ENCRYPTION_KEY`, `WHATSAPP_DELIVERY_MODE=qr`, `WHATSAPP_BRIDGE_SECRET` и `WHATSAPP_LOCAL_AGENT_ENABLED=true`. Для Google Calendar дополнительно нужны `GOOGLE_CALENDAR_CLIENT_ID` и `GOOGLE_CALENDAR_CLIENT_SECRET`. Секреты никогда не передаются в браузер и не хранятся в репозитории. `.env.worker.local` на Mac должен содержать тот же `WHATSAPP_BRIDGE_SECRET` и публичный HTTPS-адрес сайта.

Официальный WhatsApp Cloud API и старая схема n8n сохранены для обратной совместимости legacy-сценария. Клиентские Telegram и Google Calendar относятся к облачному Agent Hub и не зависят от локального QR-моста.
