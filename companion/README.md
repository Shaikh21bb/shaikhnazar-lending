# Личный агент на Mac

Агент читает выбранную папку Obsidian и обрабатывает её только на Mac. Сайт хранит зашифрованные задания, публичный ключ устройства и нейтральное расписание. Приватный ключ, тексты заметок, локальный журнал и резервные копии находятся в `~/Library/Application Support/SHAIKH/companion` с ограниченным доступом.

1. Установи Node.js 20 или новее. Открой свой кабинет на shaikh.digital и создай код подключения Mac.
2. Из папки проекта выполни команду, показанную кабинетом: `node companion/start.mjs --pair КОД --url https://shaikh.digital`.
3. Если зарегистрирована одна база Obsidian, она выбирается автоматически. При нескольких базах добавь `--vault "/полный/путь/к/базе"`.
4. Для следующих запусков открой `start-personal-agent.command`. Для остановки — `stop-personal-agent.command` или Ctrl+C в окне агента.

Компьютер должен оставаться включённым и не спать для обработки мыслей и работы WhatsApp. Зашифрованные задания ждут следующего запуска. Подключение WhatsApp начинается только по кнопке в кабинете; QR-код нужно отсканировать вручную в приложении на телефоне.

## Автозапуск на Mac

После первого сопряжения можно установить пользовательский автозапуск, чтобы не держать окно Терминала открытым:

```bash
node companion/service.mjs install
node companion/service.mjs status
```

Создаются два LaunchAgent: `digital.shaikh.companion` и `digital.shaikh.ollama`. В plist записываются только абсолютные пути Node.js, проекта и локальных журналов. Токен и приватный ключ остаются в `config.json` с правами `0600`. Папка журналов `~/Library/Application Support/SHAIKH/companion/logs` доступна только текущему пользователю.

Помощник стартует при входе в учётную запись Mac и перезапускается после сбоя. Ollama запускается с `OLLAMA_NO_CLOUD=1` на `127.0.0.1:11434`; уже работающий сторонний Ollama не останавливается и не перенастраивается. После следующего входа обёртка также ждёт, пока порт свободен, вместо запуска второго сервера. Модели не скачиваются автоматически. Автозапуск не мешает Mac переходить в сон: в спящем режиме личный агент и WhatsApp не работают.

`start-personal-agent.command` и `stop-personal-agent.command` после установки управляют фоновым помощником. Остановка снимает только задание помощника; локальная модель остаётся доступной другим приложениям. Команда `node companion/service.mjs uninstall` удаляет только два собственных задания автозапуска и их plist. Заметки, журнал, ключи и конфигурация сохраняются. Для проверки plist перед запуском есть команда `node companion/service.mjs prepare`.

## Локальная модель

По умолчанию используется уже установленный Ollama на `http://127.0.0.1:11434`. Запусти Ollama самостоятельно и выбери установленную модель через `--model ИМЯ`. Агент не скачивает модели и не включает платные или облачные замены. Другой локальный сервер с OpenAI-совместимым API можно указать через `--model-url http://127.0.0.1:1234/v1`. Допускаются только loopback-адреса; перенаправления запрещены.

Проверка без чтения заметок: `node companion/start.mjs --status`.

Если модель недоступна, мысль сохраняется в `SHAIKH Inbox` с отметкой `analysis: pending`. При запуске модели агент повторяет оформление. Он подбирает связи из существующих Markdown-заметок и создаёт задачи только при наличии в тексте. Исходная мысль сохраняется в заметке отдельным блоком, чтобы AI-пересказ не потерял детали. Неуказанные дата или время требуют уточнения: время без даты недостаточно. Автоматически распознаются «сегодня», «завтра», «послезавтра», даты `YYYY-MM-DD` или `DD.MM.YYYY` вместе с временем `HH:mm`. При нескольких сроках агент уточняет их. Даты модели не используются как источник расписания. Встречи напоминаются за 30 минут, обычные уведомления переносятся из 22:00–09:00 на 09:00 по времени Алматы.

Изменённые заметки предварительно копируются в локальную папку `backups`. Агент не удаляет заметки. Символические ссылки и пути за пределами выбранной базы не используются. Данные локального журнала никогда не загружаются на сайт. Не пересылай файл `config.json`: он содержит приватный ключ и токен Mac.

Содержание мыслей, которые ты сам отправил боту Telegram, проходит через Telegram. Вся база Obsidian и её анализ остаются локальными; уведомления с сервера нейтральные.

## Диалог в Telegram по базе Obsidian

Диалог включается отдельно после согласия владельца: ответы могут содержать сведения из заметок и сохраняются в его личном чате Telegram. После остановки помощника добавь `--telegram-dialogue` к обычной команде запуска. Для выключения есть `--no-telegram-dialogue`. Выбор сохраняется в локальном `config.json` как `telegramDialogueEnabled`; без него прежний режим сохраняет мысли и отправляет только нейтральные уведомления.

Обычным сообщением можно задать вопрос или записать новую мысль. Вопросы и уточнения не создают заметки. Агент ищет подходящие отрывки Markdown на Mac, использует последние реплики и показывает использованные источники. Если подтверждения в найденных данных нет, он должен сказать об этом. Поиск не означает, что модель одновременно прочитала каждую заметку.

- `/ask вопрос` — только ответ, без создания заметки.
- `/note мысль` — явно сохранить отдельную заметку и получить подтверждение.
- `/new` — новый контекст беседы; заметки и локальные архивы не удаляются.
- `/when идентификатор дата и время` — уточнить срок. После вопроса о сроке можно ответить обычным сообщением, например «Завтра в 12:00».
- `/help` — справка.

Тексты заметок, поисковые отрывки, запросы модели и история беседы хранятся и обрабатываются на Mac. Сайт получает только шифрованное входящее сообщение и служебные статусы. Mac получает доступ бота в зашифрованном для него конверте и отправляет ответ напрямую в Telegram API. Доступ проверяется заново перед каждой отправкой; ответы старой привязки не уходят новому владельцу. Предпросмотры внешних ссылок отключены.

Последние реплики используются в контексте модели; полные записи обработанных реплик архивируются локально в `dialogue/`. Когда модель недоступна, вопросы ждут локально и не превращаются в заметки. Очередь ответов сохраняется до отправки. Если результат отправки неизвестен после сетевого сбоя или перезапуска, агент не повторяет её автоматически: вопрос можно задать ещё раз. Нейтральные напоминания по расписанию продолжают отправляться сервером.

## Голосовые Telegram

Можно надиктовать мысль или вопрос через кнопку микрофона в личном чате бота. Mac распознаёт речь и передаёт её в тот же диалог: вопросы получают текстовый ответ, «Запомни…» сохраняет мысль в Obsidian. История учитывает распознанный текст. Произнесённые названия команд не выполняются как команды Telegram. Аудиофайлы, отправленные документом, видео и другие вложения пока не поддерживаются.

Распознавание использует MLX Whisper с уже скачанной многоязычной моделью на Apple Silicon. Зависимости устанавливаются в отдельное окружение Python 3.11 по `requirements-speech.txt`; FFmpeg должен быть установлен локально. В локальной конфигурации задаются абсолютные `speechPython`, `speechModelPath` (папка модели с `config.json` и весами) и `ffmpegPath`. Для включения после остановки помощника есть флаг `--telegram-voice`, для выключения — `--no-telegram-voice`. Также должен быть разрешён диалог Telegram. `--check` у `transcribe.py` проверяет установку без загрузки весов и без доступа к сети.

Сайт кладёт в шифрованную очередь только идентификатор файла Telegram и его параметры. Он не скачивает аудио и не распознаёт речь. Mac получает файл непосредственно у Telegram, проверяет фактический размер, декодирует локально и запускает распознавание с отключённой сетью. Веса и отсутствующие файлы не скачиваются во время обработки сообщения. Временные аудиофайлы имеют права `0600` в папке `0700` и удаляются после обработки; остатки прерванных заданий убираются при следующем запуске. Оригинальное голосовое остаётся в Telegram, как и отправленный туда текстовый ответ.

Предел одной записи — 10 минут и 19 MiB. Длительность проверяется также по декодированному аудио. Если речь не разобрана, агент просит повторить запись и не создаёт заметку. Расшифровка сохраняется в локальном журнале до вызова модели, поэтому перезапуск не должен повторно распознать уже обработанный файл или создать дубликат заметки. Долгое распознавание идёт из локальной очереди после подтверждения задания платформе.

## Правила WhatsApp в первой версии

Автоматически отправляются короткие приветствия и готовые ответы владельца при точном совпадении входящего сообщения. Все новые ответы AI сначала появляются в разделе «Мои агенты» для согласования. Деньги, обещания, встречи, личные конфликты и чувствительные данные требуют согласования даже при наличии готового примера.

API-ключ не обязателен: при недоступности бесплатного OpenRouter черновики готовит локальная модель из текущего сообщения и явно заданных правил. База Obsidian и старая переписка в этот контекст не попадают. Сгенерированный ответ всегда требует согласования. Перед выдачей QR помощник проверяет текущую версию WhatsApp Web; если её нельзя получить, старый протокол не используется.

В поле «Ваши готовые ответы» записывай каждую пару с новой строки. Между парами можно оставлять пустую строку:

```text
Сообщение: Как тебя зовут?
Мой ответ: Бекжан.

Сообщение: Чем ты занимаешься?
Мой ответ: Делаю сайты и помогаю бизнесу с автоматизацией.
```

Эти пары считаются одобренными готовыми ответами. При сравнении регистр и лишние пробелы не важны; знаки препинания учитываются. В поле помещается до 12 000 символов. История переписок не используется для обучения стилю. Правила и примеры не дают агенту разрешения самостоятельно принимать важные решения.
